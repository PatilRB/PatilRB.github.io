W-481: preserve reward claim state after reopening

Fault: reopening presents an available control despite persistent claimed state and sends a second request. Repair: derive reopened view state from the persistent claim. Failed requests still allow retry.

W-484: deduplicate replayed confirmed action history

Fault: receiving attack-1 again after reconnect adds a second history row. Gameplay application was already deduplicated. Repair: guard the history insertion by the confirmed action ID; rejected actions do not block a later valid action.

W-485: restore the item view after an invalid drop

Fault: cancelling preserves the authoritative item but leaves its view hidden until reopening. Repair: restore visibility on an invalid drop; a valid move still changes the slot once and preserves identity and quantity.
